# 架构

Better Hooks 通过明确所有权来保持精简的公开 API。包入口决定应用加载什么，Hook 契约决定任务何时可以启动，共享 Store 决定谁持有原生资源，仓库门禁则验证最终实际发布的产物。

<ArchitectureMap />

## 塑造系统的约束

- **导入安全。** 公开模块在求值时不会访问 `window`、`document`，也不会启动定时器、监听器或 React 任务。
- **提交后持有。** 长生命周期回调、订阅和异步任务在提交后启动，并提供对称清理。
- **明确的包边界。** 仅 ESM 的包同时提供根入口和每个 Hook 的独立入口，React 保持为外部依赖。
- **可观察语义。** 稳定操作、取消、过期任务保护、服务端快照与错误传播都是文档契约，而不是偶然的实现细节。
- **可测量声明。** 体积数据来自当前构建模块图；运行时声明必须由聚焦测试覆盖。

## 包拓扑

`better-hooks/use-media-query` 这样的直接导入从单个 Hook 边界开始。需要完整公开模块图时，应用仍可使用根入口 `better-hooks`。两种方式都通过显式 package exports 解析；`sideEffects: false` 让使用方工具能够判断未使用模块。

<PackageMetrics variant="summary" />

摘要测量的是应用级打包之前、未经压缩的 ES2022 输出。React 与 React DOM 是 peer dependency，不进入任何测量图。可在[性能](/zh/docs/performance)页面查看全部独立入口和准确压缩口径。

## 运行时所有权

渲染只计算值，不获取宿主资源。Effect 与 `useSyncExternalStore` 订阅负责持有定时器、事件监听器、Observer、存储通道和网络连接。当多个消费者可以安全共享同一个原生数据源时，由限定作用域的 Store 持有该数据源，并在最后一个订阅者离开后释放。

公开操作保持引用稳定，并不意味着闭包读取旧值。长生命周期任务通过在提交边界更新的 ref 读取最新回调。异步代次和取消保护会阻止已经过期的任务覆盖较新的状态。

## 变更路径

1. 每个 Hook 与对应的单元测试、SSR 测试和类型测试一同位于 `packages/hooks/src/use-*`。
2. 独立 package export 明确运行时和类型声明边界。
3. 英文与简体中文示例、参考文档描述同一份契约。
4. 包检查会导入每个构建入口，检查 client directive，测量独立入口模块图，并验证打包后的 tarball。
5. 文档以静态站点构建；浏览器级测试覆盖导航、示例、响应式布局与无障碍。

## 证据与维护

提交源码或架构变更前运行 `pnpm check`。文档界面发生变化时运行 `pnpm test:e2e`。包体积报告会在文档构建前重新生成，并在仓库验证流水线中检查是否过期。
