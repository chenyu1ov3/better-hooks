# ADR 004 — Performance evidence

## Status

Accepted.

## Context

Unqualified bundle sizes and competitor charts quickly become stale. A Hook can also be small in isolation while causing unnecessary subscriptions, repeated listener setup, or avoidable client hydration.

## Decision

Size claims come from the current built export and identify the measurement. The analyzer follows each direct ESM entry through unique relative imports, concatenates the reachable JavaScript modules once, keeps React external, and records raw, gzip, and Brotli bytes. Every direct entry has an explicit raw and gzip budget.

The generated report is committed for review, refreshed before documentation builds, and checked for drift by `pnpm check`. The website may also report manifest facts such as explicit exports and `sideEffects: false`. It does not invent competitor benchmarks, download counts, or coverage percentages.

Runtime implementations share native subscriptions only when ownership and cleanup remain clear. Documentation and examples hydrate only where interaction is required; this report itself renders as static HTML.

## Consequences

The root entry and a direct entry answer different questions and are shown separately. These values describe the package's unminified ES2022 module graphs before an application's own transforms; they are not a promise for every bundler. Build changes that exceed a budget fail validation, while unverified runtime timings remain absent rather than becoming authoritative-looking placeholders.
