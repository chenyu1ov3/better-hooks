# ADR 004 — 性能证据

## 状态

已采纳。

## 背景

缺少测量条件的包体积和竞品图表很快就会过期。即使单个 Hook 很小，也可能引入不必要的订阅、重复建立监听器，或产生可避免的客户端 hydration。

## 决策

体积声明来自当前构建入口，并明确测量口径。分析器从每个独立 ESM 入口出发，沿相对导入遍历模块图，每个可达 JavaScript 模块只拼接一次，保持 React 为外部依赖，并记录 raw、gzip 与 Brotli 字节数。每个独立入口都有明确的 raw 和 gzip 预算。

生成报告会提交到仓库供审查，在文档构建前刷新，并由 `pnpm check` 检查是否漂移。官网还可以展示显式 exports、`sideEffects: false` 等 manifest 事实，但不会编造竞品基准、下载量或覆盖率百分比。

只有所有权与清理规则保持明确时，运行时实现才会共享原生订阅。文档与示例只在真正需要交互的位置 hydration；本报告自身渲染为静态 HTML。

## 影响

根入口与独立入口回答不同问题，因此分开展示。这些数字描述应用自身转换之前、未经压缩的 ES2022 包模块图，不承诺每种打包器都产生相同结果。构建变化超过预算时验证会失败；未经验证的运行时耗时则保持缺省，不会成为看似权威的占位数字。
