# ADR 005 — 验证与发布门禁

## 状态

已采纳。

## 背景

一个 Hook 即使通过了孤立的运行时测试，仍可能缺少类型声明入口、提供不安全的服务端快照、存在示例漂移，或让最终 npm tarball 与工作区源码不一致。只验证单一层面，无法覆盖完整的发布契约。

## 决策

仓库验证沿着公开契约从源码一直检查到打包产物：

- 单元测试与 Strict Mode 测试覆盖行为、清理、取消、共享订阅和错误传播。
- 服务端渲染测试在没有浏览器全局对象的环境中执行浏览器相关 Hook，并断言快照具有确定性。
- 类型测试针对导出的声明编译根入口和独立包入口。
- 包检查会导入每个 ESM 构建入口，保留必需的 `"use client"` directive，执行逐入口体积预算，并检查打包后的 tarball。
- 示例与语言检查保证源码示例和双语文档成对存在。
- 静态文档构建验证每条路由；Playwright 覆盖浏览器工作流、响应式溢出与无障碍。

`pnpm check` 是源码与文档完整性的仓库门禁。文档界面发生变化时还需要运行 `pnpm test:e2e`。

## 影响

新增 Hook 必须让运行时代码、类型、exports、测试、示例与两种文档语言保持一致，才算完成。生成的性能证据与代码一样接受检查，因此构建图变化后不能静默保留过期的公开数字。发布自动化使用已经验证的包产物，不会重新构建一个未经检查的变体。
