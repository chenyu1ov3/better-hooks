# Support matrix

## Runtime and package

| Surface         | Current support                                  |
| --------------- | ------------------------------------------------ |
| React           | `>=19.0.0 <20.0.0`                               |
| Package modules | ESM only                                         |
| TypeScript      | declarations are generated from the typed source |
| Node.js         | `>=22.18.0`                                      |

## Rendering boundaries

| Environment             | Support boundary                                           |
| ----------------------- | ---------------------------------------------------------- |
| Client-rendered React   | Supported                                                  |
| SSR plus hydration      | Supported through documented server snapshots              |
| React Server Components | Import-safe, but Hooks must be called in Client Components |
| Browser workers         | Not a React DOM target and not claimed                     |
| React Native            | Not tested or claimed                                      |

## Browser API behavior

Hooks feature-detect the APIs they use. `useMediaQuery` falls back when `matchMedia` is unavailable. Storage Hooks preserve their current value and expose an error when storage access or serialization fails. Event Hooks skip missing targets. These fallbacks are part of the documented runtime contract.

## Frameworks

Framework compatibility follows three boundaries: React 19, ESM packages, and the relevant Client Component or hydration model. Named framework claims require dedicated integration tests.

## Update policy

This matrix describes the current manifest and implementation. A broader claim belongs here only after it is represented in tests or release validation; a framework or browser version is not implied by a passing local example.
