# Performance

Performance in a Hook library means keeping the module graph and the amount of live browser work understandable. The package documents facts that can be checked in the published artifact and avoids promises that depend on an unknown application.

## Choose an explicit package entry

Every Hook has a direct ESM entry such as `better-hooks/use-media-query`, alongside the root entry. Direct imports make ownership obvious and let bundlers start with the smallest requested graph. The package has no runtime dependency beyond the React peer dependency and declares `sideEffects: false`.

These are package properties, not a claim that every bundler or application produces the same output.

## Share native work when ownership is clear

External-store Hooks share native work where ownership and cleanup remain explicit. Media-query subscribers share an entry per `Window` and query, online status uses one listener pair per browser realm, and window size uses one resize listener for current subscribers.

## Schedule after commit and clean up first

Timer and listener setup occurs after commit. Cleanup runs when dependencies change or a component unmounts, and stable callback refs avoid rebuilding native listeners for every render.

Async, timer, and event callbacks also clean up their internal work before an error escapes. An `onError` observer can inspect the failure, but it cannot replace the original throw or rejection; stale or cancelled work may be suppressed according to its Hook contract.

## Measure the built artifact

This site does not publish competitor comparisons or synthetic benchmark numbers. Bundle figures belong only when generated from the current build and labelled with the entry, compression method, and version. Unverified numbers remain absent instead of becoming stale placeholders.
