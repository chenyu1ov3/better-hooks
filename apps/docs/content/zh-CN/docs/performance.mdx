# 性能

对 Hook 库来说，性能既包括应用请求的模块图，也包括提交后持续存活的原生任务数量。Better Hooks 会发布当前构建证据并明确适用边界，而不是给出脱离具体应用的承诺。

## 选择需要的包边界

每个 Hook 都有 `better-hooks/use-media-query` 这样的独立 ESM 入口，同时保留根入口 `better-hooks`。直接导入从单个 Hook 模块图开始；根入口暴露完整 API，仅使用部分模块时依赖使用方 tree shaking。

包除了 React peer dependency 没有其他运行时依赖，使用显式 exports，并声明 `sideEffects: false`。这些都是可验证的包属性，并不表示每种应用和打包器都会得到相同输出。

## 在所有权清晰时共享原生任务

只要所有权与清理规则保持明确，外部状态源 Hook 就会共享底层原生任务。同一 `Window` 中相同的媒体查询会复用一个条目；联网状态在每个浏览器上下文中共用一对监听器；窗口尺寸由当前订阅者共用一个 `resize` 监听器，并在尺寸未变化时跳过通知。

存储 Hook 会按存储区域和 key 共享一个提交后持有的原生通道，同时保留每个订阅者自己的 codec 与初始值语义。当共享会模糊取消或错误边界时，Observer 与网络连接 Hook 会保持实例级所有权。

## 提交后调度，先清理再报错

定时器、监听器、Observer 和网络任务只在组件提交后建立，并在依赖变化或组件卸载时清理。稳定回调 ref 可以避免仅因函数引用变化就重建原生任务。

异步、定时和事件回调会先清理内部任务，再让错误离开回调。`onError` 观察器可以检查失败，但不能替换原始抛出或 Promise 拒绝。只有 Hook 契约明确允许时，才会抑制已经过期或取消任务的错误。

## 严格解释这些证据

报告不比较竞品，不估算 React 自身开销，也不预测应用最终需要解析和执行的 JavaScript。运行时效率由所有权规则，以及针对订阅复用、相同快照抑制、取消、卸载清理和 Strict Mode 重放的聚焦测试提供证据。
