# 性能

对 Hook 库来说，“小”有两层意思：下载的代码少，页面里常驻的原生任务也少。

## 这个包有多大

<PackageMetrics />

报告测量每个未经压缩的 ES2022 入口，以及从该入口可达的内部模块。React 和 React DOM 保持为外部依赖，gzip 与 Brotli 使用 Node.js 默认参数。这是一条稳定的包级基线，不是对最终应用体积的预测。

## 只导入需要的入口

每个 Hook 都有 `better-hooks/use-media-query` 这样的独立 ESM 入口。根入口 `better-hooks` 暴露相同 API，并依赖构建工具完成 Tree Shaking。文档示例使用独立入口，因为入口边界更直观。

这个包除了 React peer dependency 没有其他运行时依赖，使用显式 exports，并声明了 `sideEffects: false`。

## 只共享真正相同的浏览器任务

多个订阅者观察同一来源时，Hook 会复用原生任务：相同媒体查询共用一个通道，联网状态在每个浏览器上下文共用一对监听器，窗口尺寸订阅者共用一个 resize 监听器。取消和错误处理无法清楚共享的 Observer 与连接，则保持实例独立。

定时器、监听器、Observer 和网络任务都在 commit 后启动，并在所有者变化或卸载时停止。稳定回调 ref 也能避免只因函数引用变化就重建任务。

## 最后还是要测真实应用

构建工具可能继续压缩、拆分、去重和转换这些代码。发布前请检查成品应用的包体积、长任务、订阅数量和无效渲染。这里的数据是起点，不是结论。
