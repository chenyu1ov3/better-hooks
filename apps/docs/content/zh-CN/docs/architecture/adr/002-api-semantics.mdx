# ADR 002 — API 语义

## 状态

已被预览版实现采用。

## 背景

如果操作函数频繁更换引用、回调读取到过期值，或取消行为含糊不清，即使 Hook 很小，也很难可靠地组合使用。

## 决策

只要语义允许，Better Hooks 返回的操作函数就会保持引用稳定。长生命周期任务始终调用最近一次已提交的回调。异步与防抖任务会在调用方需要时提供取消能力，并阻止过期的异步结果覆盖较新的状态。

受控与非受控状态共用一套更新函数契约。函数式更新接收当前模式下的最新值；当 `Object.is` 判断新旧值相等时，不会调用 `onChange`。

异常采用“传播 + 可观察”约定。Hook 回调不会静默吞掉错误：定时器、原生事件和 Promise 回调会先清理内部任务，再调用可选的 `onError` 观察器，最后保留原始的抛出或拒绝。对于已经取消或已经过期的任务，取消和过期保护可以按契约抑制其错误。

React Error Boundary 只处理子树渲染、生命周期方法和构造函数中的错误，不能捕获定时器、原生事件监听器或 Promise 回调中的错误。需要统一交给边界处理时，应用应显式把错误桥接到渲染状态，或使用 Hook 提供的 `onError` 观察器。

## 影响

实现中的 ref 会在提交边界更新。当状态或取消能力属于契约的一部分时，API 会返回小型状态对象，而不只是一个裸回调。文档需要明确说明 `leading`、`trailing`、`reset` 和回退行为。

清理是异常契约的一部分：回调失败后，除非 API 明确说明，否则不能留下仍在等待的 timeout、interval、防抖窗口、锁或事件订阅。渲染阶段的错误仍由应用负责，可交给 React Error Boundary 处理。
